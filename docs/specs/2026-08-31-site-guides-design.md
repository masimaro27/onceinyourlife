# 사이트 가이드 글 10편 — 설계

작성일 2026-08-31 · 상태: 승인됨

## 왜 만드는가

애드센스 승인 게이트의 마지막 항목이다. 도구만 있는 페이지는 Low Value Content로
거절되며, 승인된 도구 사이트는 공통적으로 도구를 감싸는 글 8~15편을 갖고 있다.

부수적 목적이 하나 더 있다. 계산기는 숫자만 내놓고 근거를 말하지 않는다.
"이 숫자가 왜 이렇게 나왔나"에 답하는 글이 있어야 계산기가 신뢰를 얻는다.

## 원재료와 중복 문제

네이버 블로그 「살면서 한 번은 겪는 일」에 8편이 발행되어 있고(2026-08-30 기준),
법령·고시 취재가 이미 끝나 있다. 이 자료를 재사용한다.

**그대로 옮기지 않는다.** 세 가지 이유다.

1. 애드센스 심사는 "기존에 없던 가치를 더하는가"를 본다. 네이버 블로그의 사본은
   부가가치 0으로 읽히며 이것이 거절 사유 1순위다.
2. 구글이 블로그 원문을 색인하고 있으면 같은 내용의 사이트 페이지는 검색에서
   걸러진다. 그러면 애드센스를 붙인 이유(애드포스트 대비 RPM 5~10배)가 사라진다.
3. 독자가 다르다. 블로그 독자는 "어떻게 신청하나"를 검색해 온다. 사이트 독자는
   **이미 계산기를 쓰고 나서** "이 숫자가 왜 이렇게 나왔지"를 묻는다.

비싼 것은 집필이 아니라 취재다. 취재 결과를 재사용하고 축은 계산기 기준으로 새로 짠다.

### 1:1 대응이 아니다

블로그 8편을 사이트 10편에 흩어 넣는다. 다음 3편은 계산기와 연결이 약해
**의도적으로 제외**한다. 억지로 넣으면 사이트 정체성이 흐려진다.

- 블로그 1편 실업급여 신청하는 곳 — 절차이지 계산이 아님
- 블로그 8편 노인돌봄서비스 — 등급이 없는 경우라 계산기 범위 밖
- 블로그 9편 상속절차 — 대응 계산기가 없음

## 구조

```
/longtermcare/guide/            가이드 목차 (index.html)
/longtermcare/guide/<slug>/     글 5편
/silup/guide/                   가이드 목차
/silup/guide/<slug>/            글 5편
```

- 도구별 자기완결 구조를 유지한다. 저장소가 이미 그 규칙을 쓴다.
- 페이지는 `assets/site.css`와 `about/`·`privacy/` 템플릿을 그대로 쓴다. 새 CSS를 만들지 않는다.
- 도구가 없는 글(상속 등)이 나중에 생기면 `/guides/`를 따로 연다.
- **sitemap은 손대지 않는다.** `gen-sitemap.mjs`가 `index.html` 있는 디렉터리를 재귀
  탐색하고 `guide`는 SKIP 목록에 없다. 글 추가 후 생성기만 다시 돌리면 된다.

## 10편 목록

각 글은 계산기를 쓴 직후의 질문에 답한다.

### `/longtermcare/guide/`

| slug | 제목 | 답하는 질문 | 재료 |
|---|---|---|---|
| `monthly-limit` | 월 한도액은 어떻게 정해지나 | 등급을 골랐더니 나온 그 한도는 뭔가 | 블로그 6 |
| `copay-rate` | 본인부담 15%가 아닌 경우 | 감경·면제는 어떻게 판정되나 | 블로그 6 |
| `home-vs-facility` | 재가와 시설, 계산이 어떻게 다른가 | 왜 시설은 한도가 없나 | 블로그 6·7 |
| `over-limit` | 한도를 넘기면 어떻게 되나 | 초과분 전액 부담과 가족휴가제 예외 | 블로그 6 |
| `not-covered` | 이 계산기가 다루지 않는 것 | 비급여·복지용구·인지활동형은 왜 빠졌나 | 블로그 6 + 계산기 면책 |

### `/silup/guide/`

| slug | 제목 | 답하는 질문 | 재료 |
|---|---|---|---|
| `how-it-works` | 구직급여는 이렇게 계산됩니다 | 산식 전체를 한 번에 | 블로그 2 |
| `average-wage` | 평균임금 3개월, 어느 3개월인가 | 이직일 입력이 무엇을 결정하나 | 블로그 2 |
| `caps` | 상한액·하한액에 걸리는 경우 | 왜 내 계산이 남과 같아졌나 | 블로그 2 |
| `benefit-days` | 소정급여일수가 정해지는 방식 | 나이·가입기간이 며칠치를 바꾸는 방식 | 블로그 2·3 |
| `why-different` | 계산기와 실제 지급액이 다른 이유 | 고용센터가 다른 금액을 말한다면 | 블로그 3·4 + 계산기 면책 |

## 글의 공통 규격

- **기준일을 명시한다.** 수가·상한액은 매년 바뀐다. 각 글 하단에 기준일과 원문 확인일을 적는다.
- **추정치임을 밝힌다.** 계산기와 같은 면책 수준을 유지한다.
- **관할 기관을 안내한다.** 장기요양 1577-1000, 실업급여 1350.
- 분량은 본문 2,000자 이상. 얇은 페이지는 애드센스 거절 사유다.
- 해당 계산기로 돌아가는 링크를 상단과 하단에 둔다.

## 도구 ↔ 글 연결

```
계산기 결과 화면 아래   →  가이드 목차 링크 ("이 숫자가 어떻게 나왔는지")
가이드 글 상·하단       →  해당 계산기
가이드 목차             →  5편 목록 + 계산기
푸터 nav                →  6링크 유지 (가이드는 도구 하위이므로 추가하지 않음)
```

## 검증

`GATES-guides.md` 원장으로 관리한다. 핵심은 **중복 콘텐츠 방어**다.

- 각 사이트 글과 대응 블로그 발행본의 문장 단위 중복률을 실측하고 임계값을 넘으면
  실패시킨다. 복사 유혹을 게이트가 구조적으로 막는다. 부정 검사는 양성 대조군으로
  탐지 능력을 먼저 증명한다.
- 그 밖에는 기존 패턴을 따른다: 페이지 구조·메타, 내부 링크 해소, 390px 렌더,
  sitemap 생성기 동기, 배포 검증, 기존 게이트 회귀.

## 페이스

주 1편 × 10주 → 2026-11월 초 게이트 충족. `부수입계획.md`의 도구 트랙 1.5h와 맞는다.

**1편을 먼저 쓰고 실제 소요를 잰다.** 1.5h 가정이 맞는지 확인한 뒤 나머지 9편 일정을
조정한다. 가정이 틀리면 페이스가 아니라 계획을 고친다.

## 이 설계가 다루지 않는 것

- 네이버 블로그 글의 작성·발행 (별도 세션 몫)
- 도구가 없는 주제의 글 (`/guides/` 신설은 필요해질 때)
- 광고 게재 자체 (승인 후 별건이며 개인정보처리방침 3항 갱신이 함께 필요)
